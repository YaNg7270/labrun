### 自研核心（运行证据）

`labrun/core`：纯 Kotlin/JVM 模块，约 1100 行，依赖只有 `kotlinx-serialization-json`。命令：

```bash
cd labrun
./gradlew :core:test
```

2026-10-08 结果：`FixedCaseTest` 4 项、`ProtocolParserTest` 3 项，**7/7 通过**。覆盖：固定案例逐行时间断言（契约 §7）、同一动作重复确认、陈旧清单不能结束、导出包重复导入跳过、杀进程恢复、重启后时间降级为估算、系统时间被拨动、回溯锚点、非法输入、路径穿越。这些是 JVM 单元测试，**不代表安卓真机提醒或界面已验证**。

## 2. 总成本比较（工程估计，不是测量值）

| 项 | ODK 适配 | 轻量自研 |
| --- | --- | --- |
| 实验执行核心（锚点、采样计划、事件流） | 要在 JavaRosa/表单模型之上加一层，或改表单核心 | 已有原型，测试通过 |
| 到点提醒 | fork 中新增，且要与表单状态同步 | 新增（安卓层），与核心事件直接对应 |
| 自由现象不打断步骤 | 与线性导航冲突，改核心 | 独立事件，原型已支持 |
| 产品前端 | 按要求整体重写 25 个 Activity/57 个题型相关界面中用到的部分，并保持与上游解耦 | 只写本产品需要的页面 |
| 电脑端 | Central 不是实验时间线工具，仍需另写处理/报告工具，外加容器部署 | 共用核心模块，直接读导出包 |
| 上游维护 | 跟进 9 万行 fork 的上游变更 | 无 |

ODK 能省下的主要是“离线结构化存储与题型控件”，而这两项在本需求中分量小（字段只有数字/整数/文本 + 照片）；它带来的改造全部落在表单核心上——正好命中开发计划“若必须大幅修改 ODK 表单核心，倾向自研”的条件。

## 3. 决定与边界

- 核心：`labrun/core`，平台无关，安卓与电脑共用，同一套重放规则保证两端对同一运行得出相同状态。
- 安卓：Kotlin + Jetpack Compose（原生），持久化用每个运行一个只追加的 JSON Lines 事件文件 + 步骤文件快照；提醒用 `AlarmManager` 精确闹钟 + 通知。
- 电脑：⚠ 形态待用户确认（见契约 §6）；读取导出包，用同一核心重算时间线与测量表。
- 因为走自研路线，开发计划阶段六“复用后整体重写前端”不适用；但统一设计规范与两端一致性验收仍照做，不额外人为重写一次。
