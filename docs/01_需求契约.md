## 2. 时间模型

- **墙上时间**：每条记录存 `epoch_ms` + 当时时区偏移（ISO 8601 输出，如 `2026-10-08T14:03:00.000+08:00`）。
- **运行时间**：`t_run_ms` = 相对全局 T0 的毫秒数。同一次开机内用单调时钟（Android `SystemClock.elapsedRealtime()`，含休眠）求差，`time_quality = "monotonic"`。
- **重启**：开始时记录开机序号（`Settings.Global.BOOT_COUNT`）。若后续事件发生在另一次开机，用墙上时间差估算，`time_quality = "wall_estimate"`，界面与导出都要显示“计时不确定”。
- **系统时间被改**：每次记录事件时比较墙上时间差与单调时间差，偏差 > 2 秒即写一条 `clock_discontinuity` 事件（含两者差值），运行时间仍以单调时钟为准。
- **用户补填的时刻**（改早的测量时刻、回溯的锚点）只能以墙上时间输入，换算为 `t_run_ms` 时以“运行开始的墙上时间”为基准，`time_quality = "user_entered"`。
- **局部时间** = `t_run_ms(事件) − t_run_ms(锚点)`；锚点未建立时为 `null`，显示“未建立”。
- 显示格式：经过时间 `+MM:SS`（≥1 小时为 `+H:MM:SS`），负值 `−MM:SS`；墙上时间 `HH:mm:ss`，跨日加日期。

## 3. 步骤文件格式（`lab-protocol-draft` 0.1）

正式 Schema：[`schema/lab-protocol-0.1.schema.json`](../schema/lab-protocol-0.1.schema.json)。固定案例无须修改即可通过。Schema 之外由解析器做的语义校验：

| 代码 | 规则 |
| --- | --- |
| E_FORMAT | `format` 必须为 `lab-protocol-draft`，`format_version` 为受支持版本（当前 `0.1`），否则报“不支持的版本”。 |
| E_DUP_ID | 步骤、锚点、采样计划、字段 ID 各自唯一。ID 只允许 `[a-z0-9_-]`，1–64 字符。 |
| E_RUN_ANCHOR | `run_start_anchor_id` 必须引用一个 `create_on.event = run_started` 的锚点；且只能有一个这样的锚点。 |
| E_REF | 锚点的 `step_id`、步骤的 `sampling_plan_ids`、采样计划的 `anchor_id`、`not_before.anchor_id` 都必须存在。 |
| E_ANCHOR_STEP_DUP | 一个步骤最多建立一个锚点。 |
| E_OFFSETS | `offsets` 非空、非负、严格递增。 |
| E_UNIT | `time_unit` 只接受 `seconds`。 |
| W_ANCHOR_ORDER | 采样计划挂在步骤 A 上但锚点由更晚的步骤 B 建立 → 警告（不阻止）。 |
| W_UNUSED | 未被引用的锚点/采样计划 → 警告。 |

导入流程：解析 → 全部错误/警告列出（带 JSON 路径）→ 预览（步骤、锚点、采样表的计划时刻）→ 无错误才允许“开始”。导入**只解析数据**，不执行任何脚本或表达式。文件上限 1 MB。

同 `protocol_id` + `protocol_version`：内容 SHA-256 相同则视为同一模板（不重复入库）；内容不同则拒绝并提示“同版本号内容不一致，请提升 protocol_version”。

给 ChatGPT 的生成提示词见 [`docs/ChatGPT步骤文件提示词.md`](ChatGPT步骤文件提示词.md)。

## 4. 记录对象（数据/接口边界）

以“只追加的事件 + 可推导的状态”为原则：落库的是事件，当前步骤、采样点状态都可由事件重放得到，便于恢复、导出和电脑端复核。

| 对象 | 关键字段 |
| --- | --- |
| Run | `run_id`, `protocol_snapshot`（原文）, `protocol_sha256`, `started_at`, `ended_at`, `status`(`running`/`ended`), `device`, `boot_count_at_start`, `tz_at_start` |
| Event（只追加） | `seq`(单调递增), `event_id`(UUID), `action_id`(客户端动作 ID，幂等键), `type`, `wall`, `t_run_ms`, `time_quality`, `payload` |
| 事件类型 | `run_started`, `step_confirmed`, `step_skipped`, `anchor_established`, `measurement_recorded`, `sample_missed`, `observation_added`, `reminder_fired`, `clock_discontinuity`, `run_ended`；更正类：`measurement_corrected`, `measurement_voided`, `sample_missed_revoked`, `step_reverted`, `anchor_corrected`, `observation_corrected`, `observation_voided`；测量表：`adhoc_table_created`, `adhoc_table_stopped` |
| Anchor（推导） | `anchor_id`, `established_wall`, `t_run_ms`, `source`(`run_started`/`step_confirmed`/`manual`/`manual_backdated`), `source_step_id`, `entered_wall` |
| SamplePoint（推导） | `plan_id`, `index`, `offset_s`, `planned_t_run_ms`, `status`(`open`/`recorded`/`missed`), `measurement_ids` |
| Measurement | `measurement_id`, `plan_id`, `point_index`(可空=计划外), `measured_wall`, `measured_t_run_ms`, `entered_wall`, `fields: {field_id: {raw, value, unit}}` |
| Observation | `observation_id`, `occurred_wall`, `occurred_t_run_ms`, `recorded_wall`, `text`, `attachments[]`, `step_id?`, `anchor_id?` |

## 5. 导出包（`labrun-package` 0.1）

文件名 `<日期>_<标题>_<run_id 前 8 位>.labrun.zip`，内容：

```
manifest.json              包格式与版本、run_id、导出时间、应用版本、文件清单（相对路径+SHA-256+字节数）
protocol.snapshot.json     开始运行时的步骤文件原文（逐字节）
run.json                   Run + 全部 Event（按 seq）
derived/timeline.csv       推导的时间线（便于直接打开；电脑端以 run.json 为准重新计算）
derived/measurements.csv   推导的测量表
attachments/<uuid>.<ext>   照片
```

规则：所有路径为相对路径、只能在 `attachments/` 或 `derived/` 下或根目录、禁止 `..`、绝对路径、盘符和反斜杠；清单外的文件、清单里缺失或哈希不符的文件都是错误。电脑端导入：`run_id` 不存在 → 新增；存在且 `run.json` 哈希相同 → “已导入，跳过”；存在但不同 → 作为该运行的新修订保存并提示，**不覆盖**。运行中导出的包 `manifest.run_status = running`，电脑端标“未结束快照”。
